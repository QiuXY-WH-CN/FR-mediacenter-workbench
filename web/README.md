# 冯如学媒协作工作台 · 新版

本项目是完整、独立的本地版本，采用纯白界面、亮橙主色、红色与金黄色辅助色，使用学媒 SOP 提供的冯如书院徽标。原工作台源码与数据保留。

## 运行

需要 Node.js 24。交付包含已经构建的 `dist/server/index.js`，日常使用不必先安装依赖：

1. 双击 `启动本地工作台.cmd`，保持窗口打开。
2. 打开 http://127.0.0.1:8766/ 。原版仍使用 8765。
3. 本机已复制原版 `.local/preview.db` 的一致性快照，账号、密码与原有工作内容继续使用；新版使用独立 Cookie，需要重新登录。之后两份数据独立变化。
4. 如果复制的是不含 `.local/` 的干净项目，首次打开 http://127.0.0.1:8766/#setup=local-preview-only-setup 创建管理员。

在启动窗口按 Ctrl+C 停止服务。端口已占用时先检查是否已经启动。服务默认仅绑定本机。需要手机同 Wi-Fi 联调时，双击 `启动局域网服务.cmd`，服务会打印局域网地址并绑定 `0.0.0.0`；这仍属于开发调试，不提供正式生产部署。

## 本次功能

### 活动、日程与模板

- 默认“空白日程”：名称、全天/起止日期与时间、地点、需求来源、对接人、活动说明；允许不创建任何任务。
- 活动详情可编辑信息、补填云盘入口、添加任务、将现有分工保存为模板。
- 模板可创建、复制编辑，创建者或管理员可编辑已有团队模板。每个环节包含建议部门、相对活动日期、截止时间、交付要求、前序环节、积分及奖励备注。
- 新建活动时选模板，再逐项确认负责人和验收人。模板变化不会修改已经生成的任务。
- 内置典礼宣传、视频制作、外派稿件、视觉设计四种 SOP 模板。照片 48 小时、视频素材 72 小时采用《素材库管理规范》细则，实际可按活动调整。
- 外派需求仅管理员/办公室负责人登记，沿用原来的管理员、部门负责人、普通成员权限模型。

### 接活、云盘与交付

- 保留时间冲突；负责人本人可“冲突已解决，恢复接活”。待修改任务恢复后仍保留退回意见。
- 每个活动可设置一个云盘上传链接，创建时可留空，之后在活动详情编辑。参与者在活动详情、任务详情及提交页面可打开或复制。
- 提交时两项核对清单提供当前活动、交付标准、截止时间、接收人和 SOP 交接要求，支持点击展开、鼠标悬停、手机长按。
- 如活动设置素材库，先打开云盘上传，再勾选上传确认。保留个人成果链接，填写后需确认访问权限。
- 上传确认记录保存当时的云盘地址、时间与提交人。后台检查提交时链接是否仍为当前入口。此确认是人工声明，不代表系统已读取或检查第三方云盘文件。
- 验收人检查实际成果后通过或退回；前序验收自动解锁后续任务。

### 积分与奖励

- 活动配置“每项任务”的默认积分及其他奖励备注；新建任务继承，未完成任务可在“调整分工”中单独修改。
- 模板环节积分留空时沿用活动默认值，明确填写 0 则表示该环节不奖励积分。
- 仅验收通过时为任务负责人记一笔账。同一任务只能入账一次；退回、提交和恢复接活不发分。
- 已完成任务的积分不随活动设置变动；不追溯补发原版历史已完成任务的积分。
- “我的积分”显示自己的累计值与明细；部门负责人可看本部门明细，管理员可看全体明细。奖励备注记录约定，实际兑现由负责人处理。

### 时间轴与同步

- 工作概览和日历页均包含同源时间轴：拖动空白处横向浏览，支持触屏滑动、月份切换、部门筛选、缩放与点击日期查看任务。
- 有活动管理权限的人可拖动 `⠿` 改期，确认后活动结束日与未完成任务同步平移。已完成任务日期不变。也可在活动编辑中直接填写日期。
- 自动定位到当前月的近期日期，日历同步显示活动时段和任务截止时间。
- 保留 30 秒自动同步；保存修改立即请求最新数据，同浏览器其他标签页收到通知后立即刷新。其他成员的独立浏览器最多等待 30 秒轮询，不宣称跨设备实时推送。
- 编辑弹窗不会因轮询被关闭或清空。页面底部原来的技术说明文字已移除。

### SOP 整合

`sop/` 是原“学媒SOP”中的 Markdown 文档快照，并含年度 CSV 参考。知识库可阅读规范、四部门手册和培训说明。办公室登记 → 分类派单 → 交付 → 验收 → 归档的逻辑已落实到活动与任务中。

新项目以数据库中的活动和任务作为界面唯一数据源；原年度 CSV 作为参考，不会自动导入为真实任务，也不会自动覆盖原文件。知识库更新后重新构建即可进入页面。

## 开发与测试

在当前项目目录执行：

```sh
pnpm install --frozen-lockfile
pnpm run build
node scripts/test.mjs
pnpm run test:mini
pnpm run dev
```

修改源码后重新构建并重启服务。数据库沿用原 SQLite 表结构，新功能数据位于有版本控制的 workspace JSON 内，兼容缺少模板与积分字段的旧数据。

`scripts/test.mjs` 使用内存数据库，覆盖原账号/权限流程与新增空白日程、模板依赖、奖励、确认机制和冲突恢复。

可选浏览器验收脚本为 `scripts/browser-test.mjs`，需可用的 Playwright 和 Edge；可设置 `PLAYWRIGHT_MODULE` 为 Playwright 入口的绝对路径。测试启动独立 8877 端口和内存数据库，测试账号及活动不会写入交付数据库。截图与结果位于 `.local/qa/`。

## 目录

| 目录 | 内容 |
| --- | --- |
| src/ | 网页、样式、服务端与新版流程逻辑 |
| src/brand/ | 原始品牌图片副本 |
| scripts/ | 构建、SQLite 本地服务、业务测试与浏览器验收 |
| db/、drizzle/ | 数据库结构和迁移 |
| sop/ | SOP 文档与历史年度排期参考 |
| dist/server/ | 可直接由本地服务运行的完整构建 |
| .local/preview.db | 本地账户与协作数据，不要公开分发 |
| .local/qa/ | 隔离测试的截图和报告 |

微信小程序端已随 `WeChatProjects/miniprogram-1` 交付；服务端通过 `scripts/mini-gateway.mjs` 提供 `/mini/api`，并可用 `启动局域网服务.cmd` 进行真机联调。相关校验见 `scripts/test-mini.mjs`。
